## 1. ปัญหาที่แก้

- ตัวอักษรและสีกระจายอยู่ทั่วโค้ดจนหน้าไหนก็หน้าตาไม่ตรงกัน และแก้ธีมทีต้องไล่แก้ร้อยที่
- **ภาษาไทยอ่านยาก** ถ้าเลือกฟอนต์/ระยะบรรทัดไม่เหมาะ (สระ-วรรณยุกต์ซ้อน, ตัวเลขไม่เท่ากัน)
- สีที่ "ดูสวย" แต่ **contrast ไม่ผ่าน** (สีแบรนด์เขียวมิ้นต์/ส้มคอรัลบนพื้นขาวอ่านไม่ออก) และสื่อความหมายด้วยสีอย่างเดียว
- iPhone **ซูมหน้าอัตโนมัติ** เมื่อแตะช่องกรอกที่ตัวอักษรเล็กกว่า 16px
- ร้านแต่ละร้านต้องเปลี่ยนสีได้ โดยหน้าไม่อ่านไม่ออก

## 2. สรุปสั้น

1. **ฟอนต์ 2 ตัว ซ้อนกันเป็น stack เดียว**: `Geist` (ละติน/ตัวเลข) → `Noto Sans Thai` (ไทย) → `ui-sans-serif, system-ui, sans-serif` ฝังไฟล์เองผ่าน npm (`@fontsource-variable/*`) ไม่ยิงไป Google ตอนใช้งาน · เป็น **variable font** น้ำหนัก 100–900 · `font-display: swap`
2. **สเกลตัวอักษรใช้จริงมีแค่ 8 ขั้น** (rem ตาม Tailwind): 12 · 14 · 16 · 18 · 20 · 24 · 30 · 36 px — **ตัวหนังสือเนื้อหา/ปุ่ม/ช่องกรอก = 16px** · คำอธิบาย = 14px · เล็กสุด 12px (ป้ายเมนูล่างมือถือ/ตัวเลขบนกระดิ่งเท่านั้น)
3. **น้ำหนักตัวอักษร 4 ระดับ**: 400 (เนื้อหา) · 500 (ป้ายกำกับ/เมนู) · 600 (ปุ่ม/ชื่อรายการ/เน้น) · 700 (หัวข้อ/ราคา/ตัวเลขสำคัญ) — **ไม่มีตัวเอียง ไม่มีตัวพิมพ์ใหญ่ล้วน** (ภาษาไทยไม่มีแนวคิดนี้)
4. **ระยะบรรทัดฐาน 1.6** (`body`) เพราะภาษาไทยต้องการ — แต่ **ยูทิลิตี้ `text-sm`/`text-xs` ของ Tailwind ตั้ง line-height เองให้แน่นขึ้น** (20px/16px) จึงใช้กับข้อความบรรทัดเดียวเป็นหลัก (§5)
5. **สีมาจาก token เท่านั้น** (`bg-primary` `text-ink` …) ค่า hex อยู่ไฟล์เดียว มี lint กัน: 25 ตัวแปรสี (หลัก 14 · สถานะ 8 · ปิดใช้งาน 2 · เงา 1) — **สีแบรนด์ `#00B8A9` และส้ม `#FF876B` เป็น "พื้น" เท่านั้น ข้อความบนพื้นสองสีนี้ใช้ `ink`** (ขาวบนสองสีนี้ contrast 2.49/2.35 ไม่ผ่าน)
6. **เป้าแตะขั้นต่ำ 44px** · ช่องกรอก 16px · focus ring 3px สี `primary` · สถานะไม่สื่อด้วยสีอย่างเดียว (ไอคอน+ข้อความเสมอ)
7. **ธีมต่อร้านเปลี่ยนได้แค่ 5 สี** (`primary` `ink` `bg` `accent` `surface`) ผ่านตัวตรวจ contrast ในโค้ด — **ฟอนต์ไม่เปลี่ยนตามร้าน**

### 3.2 วิธีเก็บสีให้เปลี่ยนที่เดียว (Tailwind v4)

```css
/* theme.css — ไฟล์เดียวที่มี hex: ตัวแปรดิบ --sn-* */
:root { --sn-primary: #007f76; --sn-ink: #082b4c; --sn-bg: #f4fbfa; /* … */ }

/* app.css — ผูกเข้า Tailwind: ใช้ bg-primary, text-ink, border-line ได้ทันที */
@import 'tailwindcss';
@import './theme.css';
@theme inline { --color-primary: var(--sn-primary); --color-ink: var(--sn-ink); --color-bg: var(--sn-bg); /* … */ }
```

- `@theme inline` ทำให้ utility อ้าง `var(--sn-*)` **ตอนรัน** → ธีมต่อร้านแค่ใส่ `style="--sn-primary:#…"` ที่ราก `<html>` ก็เปลี่ยนทั้งหน้าร้านโดยไม่ build ใหม่
- กฎ: **ห้าม hex/`rgb()` นอก `theme.css`** — ตรวจด้วย `scripts/check-no-hex.mjs` (รันใน `npm run check`) ข้อยกเว้นเดียวคือค่าที่ส่งให้เบราว์เซอร์ตรง ๆ (`<meta name="theme-color">` ใน `config/brand.ts`)

### 3.3 ธีมต่อร้าน

- ร้านตั้งได้ 5 สี: `primary` `ink` `bg` `accent` `surface` (ค่าที่ไม่ตั้ง = ใช้ของแพลตฟอร์ม) ผ่าน `validateTheme`: `ink`/`primary` บน `bg` และ `surface` ≥ 4.5 · `ink` บน `accent` ≥ 4.5 · มีสีข้อความบน `primary` ที่ผ่าน (`onColor`: เลือก `ink` → ขาว → ดำ ตัวแรกที่ ≥ 4.5) · ไม่ผ่าน = **ไม่บันทึก** บอกสาเหตุ
- ฉีดเป็นตัวแปร CSS (`themeStyle`) เฉพาะชื่อที่กำหนด ค่ารับเป็น `#rrggbb` เท่านั้น (ไม่รับ CSS/HTML อื่น) · อ่านจากฐานข้อมูลแบบทนทาน (`safeTheme`): ข้อมูลเก่า/เสีย = ธีมแพลตฟอร์ม ร้านไม่พัง
- ข้อสังเกต: ธีมร้านตั้ง `primary-hover` และ `primary-pressed` = `primary` (ปุ่มไม่เปลี่ยนเฉดตอน hover) — ถ้าต้องการเฉด hover ต่อร้านต้องคำนวณเพิ่ม
- ส่วนจัดการ (`/admin`, `/manage`) **ไม่เปลี่ยนตามร้าน** ใช้ธีมแพลตฟอร์มเสมอ

น้ำหนัก: `font-semibold` 164 · `font-medium` 60 · `font-bold` 50 · `font-normal` 3

หมายเหตุสำคัญ:

- ขนาดเป็น **rem** (ไม่ใช่ px ตายตัว) → เคารพการตั้งขนาดตัวอักษรของเบราว์เซอร์/ระบบของผู้ใช้
- **ขนาดไม่เปลี่ยนตามความกว้างจอ** (390 กับ 1280 ได้ค่าเดียวกัน) ยกเว้นแบนเนอร์ใหญ่ 1 จุด (`md:text-4xl`) — ใช้การจัดวาง (grid/flex-wrap) ปรับตามจอแทนการย่อฟอนต์
- สีของข้อความจับคู่ตามพื้น: พื้นอ่อน → `ink`/`muted` · พื้น `primary` → ขาว · พื้น `brand`/`accent`/`highlight` → `ink` เสมอ

## 5. กฎที่ห้ามละเมิด

1. **ช่องกรอก/select/textarea 16px ขึ้นไป** (กัน iOS ซูม) · เป้าแตะ ≥ 44px (`min-h-11`)
2. **ข้อความเล็กกว่า 14px ใช้จำกัด** — 12px เฉพาะป้ายเมนูล่างมือถือและตัวเลขบนกระดิ่ง (ข้อความสั้นมาก บรรทัดเดียว)
3. **ข้อความไทยหลายบรรทัดห้าม `leading-none`/`leading-tight`** — ภาษาไทยมีสระและวรรณยุกต์ซ้อนทั้งบนและล่าง ต้องการระยะบรรทัด ≥ 1.4 (ฐานของระบบ 1.6)
4. สีทุกค่ามาจาก token — **ห้าม hex/rgb ในไฟล์หน้าจอ** (มี lint)
5. **ข้อความบนพื้น `brand`/`accent`/`highlight` ใช้ `ink`** · ห้ามตัวอักษร/ไอคอน/ขอบสี `brand`/`accent` บนพื้นอ่อน (contrast 2.49/2.35)
6. ข้อความสี `primary` บนพื้น `mint` ใช้ `primary-hover` (4.34 → 6.08)
7. **ขอบช่องกรอกใช้ `field-border`** (3.76:1) ไม่ใช่ `line` (1.25:1)
8. สถานะ (สำเร็จ/เตือน/ผิดพลาด/เลือกอยู่) ต้องมีไอคอนหรือข้อความกำกับ — ไม่สื่อด้วยสีอย่างเดียว · แดงใช้กับข้อผิดพลาด/การลบเท่านั้น `accent` ห้ามใช้เป็นสีเตือน/ผิดพลาด
9. ตัวเลขเงิน/จำนวน/ยอดรวม ใช้ `tabular-nums` (และชิดขวาในตาราง)
10. ไม่ให้ผู้ใช้/AI กำหนดฟอนต์หรือ CSS อิสระ — ธีมต่อร้านรับเฉพาะ `#rrggbb` 5 ค่าที่ผ่านตัวตรวจ contrast
11. ฟอนต์ฝังจาก bundle (ไม่เรียก Google Fonts ตอนใช้งาน) และต้องมีฟอนต์สำรองใน stack

## 7. ลอกไปใช้อย่างไร

1. ติดตั้งฟอนต์: `npm i @fontsource-variable/geist @fontsource-variable/noto-sans-thai` แล้ว `@import` ใน CSS หลัก (ภาษาอื่น: เปลี่ยนตัวที่สองเป็นฟอนต์ของภาษานั้น ให้ละตินอยู่ตัวแรก)
2. ตั้ง stack ใน `@theme inline { --font-sans: … }` และ `body { font-size: 1rem; line-height: 1.6 }`
3. เก็บสีเป็นตัวแปร `--<prefix>-*` ไฟล์เดียว + ผูก `@theme inline` + เขียน lint กัน hex นอกไฟล์นั้น
4. เลือกสีตามบทบาท (§3.1) และ **คำนวณ contrast ทุกคู่ก่อนใช้**: ข้อความปกติ ≥ 4.5 · ข้อความใหญ่/ไอคอน/ขอบช่องกรอก ≥ 3 — สีแบรนด์ที่สว่างให้เป็น "พื้น" แล้วจับคู่ข้อความสีเข้ม แทนการใช้เป็นตัวอักษร
5. ใช้สเกล 12/14/16/18/20/24/30/36 และน้ำหนัก 400/500/600/700 ตาม §4.2 — เขียนเป็นคลาสส่วนกลาง (`.btn` `.field` `.label` `.card` `.table` `.notice` `.navitem`) แทนการแปะ utility ซ้ำทุกหน้า
6. ถ้ามีธีมต่อลูกค้า: จำกัดจำนวนสีที่ให้แก้, รับเฉพาะ `#rrggbb`, ตรวจ contrast ที่ server ตอนบันทึก, ฉีดเป็นตัวแปร CSS ที่ราก, อ่านกลับแบบทนข้อมูลเสีย
7. เทส: lint ไม่มี hex นอก theme · เทส contrast ของทุกคู่ใน token · axe ไม่มีปัญหาร้ายแรงที่ 390×844 และ 1280×800 ทั้งสองภาษา · เทสธีมต่อร้านที่ไม่ใช่ธีมเริ่มต้นอย่างน้อยหนึ่งชุด

## 8. สถานะ

- ค่าสี/ฟอนต์ใน `theme.css`/`app.css` ตรงกับโค้ดที่ deploy ล่าสุด · ตัวเลขใน §4.2 วัดจากเบราว์เซอร์ (Chromium) ในเครื่องทดสอบ ไม่ใช่เบราว์เซอร์/ระบบปฏิบัติการทุกแบบ (ฟอนต์สำรองของระบบอาจต่างกันเล็กน้อยหากฟอนต์ฝังโหลดไม่ได้)
- ยังไม่มีธีมมืด (dark mode) — ชุดสีนี้เป็นธีมสว่างอย่างเดียว
