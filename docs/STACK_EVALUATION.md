# การประเมินชุดเทคโนโลยีที่เสนอ

> อัปเดตหลังอนุมัติ: C-07 เลือก Next.js/React/TypeScript/npm แล้ว ข้อความต่อไปนี้เป็นประวัติการประเมินเดิม
> รุ่นที่ล็อกจริงและผลติดตั้ง/build/ทดสอบอยู่ใน package.json และ [รายงานชิ้นงาน](IMPLEMENTATION_REPORT.md)
> อ่านเอกสาร Next ที่มากับแพ็กเกจรุ่นติดตั้งเพื่อตรวจ params/searchParams แบบ Promise และการติดตั้ง

ประเมินวันที่ 2026-11-04 คลังงานไม่มีข้อเสนอชุดเทคโนโลยีเดิม จึงเป็นการประเมินตัวเลือกใหม่
ยังไม่ใช่การอนุมัติหรือจัดเตรียมบริการ รอบวางแผนก่อนหน้าอ่านเอกสารต้นทางทางการสำเร็จ
ผ่าน HTTPS โดยตรวจ TLS ตามปกติ แหล่งข้อมูลเป็นสาขาพัฒนาที่เปลี่ยนแปลงได้
ต้องตรวจเอกสารตรงกับรุ่นเสถียรที่จะล็อกอีกครั้งเมื่ออนุมัติให้พัฒนา
ไม่ได้ติดตั้งแพ็กเกจหรือทดสอบความเข้ากันได้ และรอบแปลภาษาไม่ได้ดึงเอกสารใหม่

| ตัวเลือก | สิ่งที่พบจากเอกสารทางการ | ความเหมาะสมและข้อแลกเปลี่ยน |
| --- | --- | --- |
| Next.js App Router / React / TypeScript | เอกสารติดตั้งระบุ Node >=20.9, TypeScript >=5.1; Next 16+ ไม่ทำ lint ระหว่าง build; เอกสารหลายภาษาใช้เส้นทางภาษาและ app/[lang] | เสนอ P-02 สำหรับไดเรกทอรีที่อาจมีงานฝั่งเซิร์ฟเวอร์ภายหลัง; แยก lint เป็นขั้นตรวจ ใช้เส้นทางสองภาษาและพจนานุกรมในโครงการ ไม่ต้องมีบริการแปลภายนอก แต่ซับซ้อนกว่าชิ้นงานสถิต |
| Vite/React แบบสถิต | ยังไม่ได้ศึกษาเอกสารเฉพาะรุ่นในรอบนี้ จึงไม่อ้างความเข้ากันได้ | เหมาะหากเจ้าของต้องการเว็บสถิตต่อเนื่อง; ส่วนรันเล็กลง แต่ต้องออกแบบเซิร์ฟเวอร์เพิ่มภายหลังและตรวจเอกสารก่อนเลือก |
| Playwright | เอกสารแนะนำรองรับชุดทดสอบแยกเบราว์เซอร์และติดตั้งไบนารี/ส่วนประกอบระบบ; แหล่งข้อมูลที่อ่านระบุ Node 22/24/26 และ Debian/Ubuntu ที่รองรับ | ใช้ทดสอบภาษา สถานะ คีย์บอร์ด และผลว่าง; ล็อกรุ่นเครื่องมือกับเบราว์เซอร์ ตรวจระบบปฏิบัติการและ Node LTS ที่ยังรองรับ; เริ่ม CI ด้วยหนึ่ง worker |
| Vitest + axe-core | เป็นข้อเสนอ ยังไม่ได้อ่านเอกสารเฉพาะรุ่นหรือตรวจความเข้ากันได้ในรอบนี้ | ทดสอบวันหมดอายุ/ตัวกรองและการเข้าถึงแบบอัตโนมัติ; ต้องตรวจรุ่นเสถียรก่อนล็อก การสแกนอัตโนมัติไม่ยืนยัน WCAG ครบทั้งหมด |
| PostgreSQL — ระยะหลังเท่านั้น | ต้องเปิด RLS; เมื่อเปิดแต่ไม่มีนโยบายจะปฏิเสธโดยปริยาย; เจ้าของตาราง ผู้มี BYPASSRLS และ superuser ข้ามนโยบายได้; นโยบายแบบ permissive รวมด้วย OR | เหมาะกับข้อมูลหลายองค์กร หลักฐาน และความยินยอม; แยกบทบาทย้ายโครงสร้างกับบทบาทแอป ทดสอบ USING และ WITH CHECK; RLS ไม่แทนการตรวจสิทธิ์หรือแคชที่ปลอดภัย ชิ้นงานแรกไม่ต้องใช้ฐานข้อมูล |
| เป้าหมาย WCAG 2.2 AA | W3C ระบุเกณฑ์ที่ไม่ผูกกับเทคโนโลยีและต้องใช้การตรวจอัตโนมัติร่วมกับคน | ตรวจคีย์บอร์ด โฟกัสที่มองเห็น/ไม่ถูกบัง การประกาศสถานะ ขนาดเป้าหมาย ภาษา ความต่างสี การจัดหน้าใหม่ และข้อผิดพลาด; ยังต้องตรวจคำแปลและโปรแกรมอ่านหน้าจอด้วยคน |

ชิ้นงานแรกที่เสนอใช้เพียง Node, npm registry และเบราว์เซอร์/ส่วนประกอบระบบของ Playwright
ไม่ต้องมี API key บัญชีคลาวด์ ระบบยืนยันตัวตน ฐานข้อมูล อีเมล การชำระเงิน หรือผู้ให้บริการ AI
ไม่ได้เปลี่ยนการตั้งค่าเครือข่าย ต้องตรวจปลายทางดาวน์โหลดและทรัพยากรจริงตอนตั้งโครงการ
ใช้ฟอนต์/ไฟล์ในโครงการและไม่ส่งสถิติภายนอก เลือก Node LTS ที่ยังรองรับและตรงกับรุ่นเครื่องมือ
พร้อมบันทึกรุ่น runtime ตัวจัดการแพ็กเกจ และ lockfile อย่างเจาะจง
