# Knowledge: Responsive Web Design — แอปเดียวใช้ได้ทั้งมือถือและเดสก์ท็อป (จากระบบ RooSuk)

> อ้างอิงโค้ดจริง: `src/components/shell/AppShell.tsx` (โครงหลัก, sidebar, header, bottom bar, แผ่น "เพิ่มเติม") · `src/config/nav.ts`
> · `src/app/globals.css` (Tailwind 4 tokens, `.btn`, `.field`, `.card`, ธีมมืด) · `src/components/home/*` (การ์ดหน้าแรก, `ScrollHint`)
> · `e2e/shell.spec.ts`, `e2e/pages.spec.ts`, `e2e/home.spec.ts` (Playwright 390×844 และ 1280×800 + axe) · `playwright.config.ts`
> แนวคิดตั้งต้น: `docs/01-responsive-layout.md` และ `docs/02-navigation.md` (จากโครงการก่อนหน้า) — ไฟล์นี้คือสิ่งที่ RooSuk ใช้จริงและเพิ่มเติม

---

## 1. ปัญหาที่แก้

ผู้ใช้ส่วนใหญ่เปิดจากมือถือ (มักติดตั้งเป็น PWA ซึ่ง **ไม่มีแถบเบราว์เซอร์และไม่มีปุ่ม Back**) ส่วนเจ้าหน้าที่ใช้ทั้งมือถือและคอมพิวเตอร์
ต้องมีโค้ดหน้าจอชุดเดียวที่ใช้ได้ทั้งสองแบบ โดยไม่มีจุดพังที่พบบ่อย: เลื่อนซ้ายขวาได้, ปุ่มเล็กกดยาก, bottom bar ทับบรรทัดสุดท้าย,
แผ่นเมนูยาวเกินจอโดยไม่รู้ว่าเลื่อนได้, ช่องกรอกที่ทำให้ iPhone ซูมเอง

## 2. สรุปสั้น

1. **Mobile-first และ breakpoint โครงหลักจุดเดียว `md` (768px)**: เล็กกว่า = มือถือ (header บน + bottom bar + แผ่น "เพิ่มเติม"), ตั้งแต่ = เดสก์ท็อป (sidebar)
2. **เนื้อหากว้างสุด `max-w-3xl`** อ่านง่ายบนจอใหญ่ ไม่ต้องทำ layout แยก
3. **เป้าการแตะ ≥ 44px** ทุกปุ่ม/ลิงก์ในแถบและฟอร์ม (`min-h-11`), ตัวอักษรในช่องกรอก 16px (`text-base`) กัน iOS ซูม
4. **safe-area** ของ iPhone: bottom bar และแผ่นเมนูเว้น `env(safe-area-inset-bottom)`; เนื้อหาเว้นที่ให้ bar
5. **ไม่มีการเลื่อนแนวนอนทั้งหน้า** — ตารางกว้างอยู่ในกล่อง `overflow-x-auto` ของตัวเอง; เทสตรวจ `scrollWidth <= clientWidth`
6. **เมนูชุดเดียว** (`src/config/nav.ts`) สร้างทั้ง sidebar, bottom bar, แผ่น "เพิ่มเติม" และการ์ดหน้าแรก — ไม่มีรายการซ้ำสองที่
7. **เทสจริงที่ 390×844 และ 1280×800** ทุกครั้ง (Playwright + axe accessibility) ด้วยหน้า `/preview/*` ที่ไม่ต้องมี backend
8. ธีมสว่าง/มืด (ระบบ + สลับเอง) ผ่าน CSS variables; หน้าพิมพ์ (ใบเสร็จ ฉลาก) ซ่อนโครงแอปด้วย `print:hidden`

## 3. โครงที่ใช้

### 3.1 โครงหลัก (`AppShell`)

```tsx
<div className="bg-background min-h-screen md:flex">
  <aside className="sticky top-0 hidden h-dvh w-60 shrink-0 flex-col overflow-y-auto border-r md:flex print:hidden!">
    …sidebar…
  </aside>
  <div className="flex min-w-0 flex-1 flex-col pb-[calc(4rem+env(safe-area-inset-bottom))] md:pb-0">
    <header className="sticky top-0 z-30 h-14 backdrop-blur md:hidden print:hidden! …">
      โลโก้ · ภาษา · ธีม · แจ้งเตือน
    </header>
    <main className="mx-auto w-full max-w-3xl flex-1 px-4 py-5 md:px-6 md:py-8">
      <BackLink />
      {children}
    </main>
  </div>
  <nav className="fixed inset-x-0 bottom-0 z-40 pb-[env(safe-area-inset-bottom)] md:hidden print:hidden!">
    …bottom bar 5 ช่อง…
  </nav>
  {moreOpen ? (
    <div className="fixed inset-0 z-50 md:hidden">
      …แผ่น "เพิ่มเติม" สูงสุด 85dvh…
    </div>
  ) : null}
</div>
```

จุดที่ต้องสังเกต: `min-w-0` (ไม่ให้ flex child ดันความกว้างเกินจอ), `h-dvh` (ความสูงจริงของมือถือเมื่อแถบเบราว์เซอร์ยุบ/ขยาย),
padding-bottom ของคอลัมน์เนื้อหา = ความสูง bar + safe-area (บรรทัดสุดท้ายไม่ถูกบัง)

### 3.2 แถบล่างบนมือถือ

- 5 ช่องกว้างเท่ากัน ลูกค้า: หน้าแรก · ถาม AI · **สแกน (ยกสูง อยู่กึ่งกลางพอดี)** · ผู้ช่วยสุขภาพ · เพิ่มเติม
- แต่ละบทบาทมีแถบของตัวเอง (แอดมิน: ภาพรวม · รายได้และกำไร · ร้านค้า · แจ้งเตือน)
- ป้ายใต้ไอคอนใช้ `NavItem.short` ได้ (คำสั้นกว่าในเมนู, ขึ้นบรรทัดใหม่ด้วย `\n` + `whitespace-pre-line`)
- "เพิ่มเติม" ติดสีเฉพาะเมื่อหน้าที่เปิดอยู่เป็นเมนูที่อยู่ในแผ่นนั้น (`moreActive`); เมนูที่ใช้งานอยู่ = href ที่ยาวที่สุดที่ตรง (`activeNavHref`)

### 3.3 แผ่น "เพิ่มเติม"

- รายการที่ไม่อยู่ในแถบ (และไม่อยู่บนการ์ดหน้าแรก) จัดกลุ่มตามหัวข้อเดียวกับ sidebar
- สูงสุด 85% ของจอ เลื่อนในตัวเอง พร้อม **สัญลักษณ์บอกว่ามีรายการซ่อนด้านบน/ล่าง**; เปิดแล้วเลื่อนไปให้เห็นเมนูของหน้าปัจจุบัน
- ปิดด้วย ✕ / แตะพื้นหลัง / Esc / **ปุ่ม Back ของเครื่อง** (ดู `docs/BACK-BUTTON-KNOWLEDGE.md`)
- จำว่าเปิดไว้ที่ path ไหน และลืมทันทีที่ path เปลี่ยน (ไม่เด้งขึ้นเองเมื่อกลับมาหน้าเดิม)

### 3.4 หน้าแรกแบบการ์ด (ลูกค้า)

- การ์ด 2 ขนาด: "wide" เต็มแถว, "half" มาเป็นคู่ (`grid-cols-2`) — ข้อมูลการ์ดอยู่ใน `HOME_CARDS` ใน `nav.ts` (การ์ด = เมนูเดียวกัน, เทาเมื่อฟีเจอร์ปิด)
- `ScrollHint` ลอย "เลื่อนลง / กลับขึ้นบนสุด" เมื่อการ์ดล้นจอ (คนไม่รู้ว่ามีการ์ดด้านล่าง)
- ภาพประกอบเป็น SVG วาดเอง (คมทุกขนาด ไฟล์เล็ก)

### 3.5 ส่วนประกอบพื้นฐาน (`globals.css`)

| class    | กฎ                                                                                                                                |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `.btn`   | `inline-flex min-h-11 items-center justify-center gap-2 rounded-xl px-5 text-base font-semibold`, disabled จางและเคอร์เซอร์ห้าม   |
| `.field` | `min-h-11 w-full rounded-xl border px-3 text-base` (16px — iOS ไม่ซูม)                                                            |
| `.card`  | กล่องเนื้อหามาตรฐาน; เทสใช้ `.card` ตัวสุดท้ายตรวจว่าไม่ถูก bar บัง                                                               |
| สี       | tokens ใน `:root` + `prefers-color-scheme: dark` + `[data-theme="dark"]`; ข้อความไม่ใช้ดำสนิท, สีแดงสดสงวนไว้สำหรับค่าผิดปกติจริง |

ปุ่มที่สั่งงานช้า: `SubmitButton` / `PendingButton` (spinner + disabled ระหว่างทำงาน) — กดซ้ำไม่ได้

### 3.6 เทส (ตัวอย่างจาก `e2e/shell.spec.ts`)

- มือถือ: bottom bar แทน sidebar และ **ไม่มีเลื่อนแนวนอน** · ปุ่มสแกนยกสูงอยู่กึ่งกลางพอดี · **ทุกช่องในแถบสูง ≥ 44px และกว้างเท่ากัน 5 ช่อง**
  · **bar ไม่บังบรรทัดสุดท้าย** · หน้าปัจจุบันถูกระบุในแถบ (`aria-current`) · แผ่นเมนูเปิด/ปิด/Esc/Back · เมนูของฟีเจอร์ที่ปิดเป็นสีเทาและกดไม่ได้
- เดสก์ท็อป: sidebar แทน bar และสูงเต็มจอ · กลุ่ม/สถานะเมนู · **คอลัมน์เนื้อหาถูกจำกัดความกว้าง**
- ทุกหน้า: axe ไม่มี violation ระดับร้ายแรง, `document.documentElement.scrollWidth <= clientWidth`

## 4. กฎที่ห้ามละเมิด

1. เขียน mobile ก่อน แล้วเพิ่ม `md:` — ไม่เพิ่ม breakpoint ใหม่ให้โครงหลัก
2. ทุกเป้าการแตะ ≥ 44px; ช่องกรอก 16px ขึ้นไป
3. ห้ามมีอะไรกว้างเกินจอ: รูปใช้ `max-w-full`, ตาราง/โค้ดอยู่ใน `overflow-x-auto`, ข้อความยาวไม่มีช่องว่าง (URL, รหัส) ใช้ `break-all`/`break-words`
4. องค์ประกอบ fixed ด้านล่างต้องเว้น safe-area และเนื้อหาต้องเว้นที่ให้มัน
5. เมนูมาจากรายการเดียว — เพิ่มหน้าใหม่ = เพิ่มใน `nav.ts` ที่เดียว
6. ทุกหน้าที่อยู่ลึกกว่าเมนูต้องมีลิงก์ "กลับไป…" (PWA บน iPhone ไม่มีปุ่ม Back)
7. หน้าใหม่ต้องมี fixture ใน `/preview/*` และเทสที่ 390×844 กับ 1280×800

## 5. บทเรียนจากของจริง

| เกิดอะไร                                        | สาเหตุราก                           | แก้อย่างไร                                               |
| ----------------------------------------------- | ----------------------------------- | -------------------------------------------------------- |
| บรรทัดสุดท้ายของทุกหน้าถูก bottom bar บัง       | เว้น padding คงที่ ไม่รวม safe-area | `pb-[calc(4rem+env(safe-area-inset-bottom))]` + เทสตรวจ  |
| แผ่นเมนูยาวขึ้นจนรายการล่างหลุดจอโดยไม่มีใครรู้ | ไม่มีสัญลักษณ์ว่าเลื่อนได้          | จำกัด 85dvh + ลูกศร/เงาบอกรายการที่ซ่อนอยู่              |
| แผ่น "เพิ่มเติม" เด้งขึ้นเองเมื่อกลับมาหน้าเดิม | state "เปิด" ไม่ผูกกับ path         | จำ path ที่เปิด และลืมทันทีที่ path เปลี่ยน (`seenPath`) |
| ป้ายเมนูภาษาไทยยาวเกินช่องในแถบ                 | ใช้ชื่อเมนูเต็มในแถบ                | `short` สองบรรทัด                                        |
| iPhone ซูมเข้าเมื่อแตะช่องกรอก                  | font-size < 16px                    | `.field` ใช้ `text-base`                                 |

## 6. ลอกไปใช้อย่างไร

1. วาง `AppShell` ตามโครง §3.1 (breakpoint เดียว, `min-w-0`, `h-dvh`, safe-area, `max-w-3xl`)
2. `nav.ts` รายการเดียว (กลุ่ม, ไอคอน, `short`, `flags`) + ฟังก์ชันเลือกเมนูที่ active
3. `.btn` / `.field` / `.card` / tokens สี + ธีมมืด
4. หน้า `/preview/*` ที่เปิดเฉพาะเมื่อ `ENABLE_UI_PREVIEW=1` เพื่อเทส layout โดยไม่ต้องมีฐานข้อมูล
5. Playwright สองขนาดหน้าจอ + axe + เทสพื้นฐานใน §3.6 ตั้งแต่วันแรก
