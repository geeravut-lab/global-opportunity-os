## 1. ปัญหาที่แก้

เมนูยาวขึ้นเรื่อย ๆ ตามบทบาทและฟีเจอร์ (Super Admin มากกว่า 8 รายการ) แต่ความสูงจอไม่เท่ากัน: จอโน้ตบุ๊กเตี้ย ๆ, หน้าต่างที่ย่อ, มือถือที่แถบ URL กินที่, มือถือจอเล็ก
ถ้าไม่ออกแบบให้เลื่อนได้ จะเกิด 3 อย่าง:

1. เมนูท้ายรายการ **ถูกตัดทิ้งโดยไม่มีทางเข้าถึง** (หรือดันปุ่ม "ออกจากระบบ" ท้าย sidebar ตกขอบจอ)
2. ทั้งหน้า (sidebar + เนื้อหา) เลื่อนไปพร้อมกัน เมนูหลุดจอ ต้องเลื่อนกลับขึ้นไปหาเมนู
3. บนมือถือ แผ่นเมนูยาวเกินจอแต่ผู้ใช้ **ไม่รู้ว่าเลื่อนได้** จึงไม่เห็นเมนูที่เหลือ

## 2. สรุปสั้น

1. **Desktop**: sidebar สูงเท่าจอและติดขอบบน (`sticky top-0 h-dvh`) — โลโก้/กระดิ่งอยู่บน ปุ่มบัญชี/ออกจากระบบอยู่ล่าง **มีเฉพาะรายการเมนูตรงกลางที่เลื่อนได้** (`flex-1 overflow-y-auto overscroll-contain`)
2. **มือถือ**: แถบล่างคงที่ = เมนูหลัก 4 รายการ + ปุ่ม **"เพิ่มเติม"**; ที่เหลือทั้งหมด (รวมบัญชี/ภาษา/ออกจากระบบ) อยู่ในแผ่นที่เด้งจากด้านล่าง
3. **แผ่น "เพิ่มเติม" สูงไม่เกิน 85% ของจอ** (`max-h-[85dvh]`) แล้วเลื่อนในตัว — มี **ลูกศรขึ้น/ลง** บอกว่ายังมีเมนูให้เลื่อนดู (กดเลื่อนครั้งละ ~60% ของความสูงแผ่น) ลูกศรหายเมื่อสุดทาง และไม่โผล่เลยถ้าเมนูพอดีจอ
4. เปิดแผ่นแล้ว **เลื่อนมาให้เห็นเมนูที่เปิดอยู่ตรงกลางแผ่นเอง** (ไม่ต้องไล่หา)
5. **เลื่อนจนสุดแล้วไม่ลามไปเลื่อนหน้าด้านหลัง** (`overscroll-contain`)
6. ลูกศรบอกการเลื่อน **ต้องไม่ถูกตัวบอกสถานะ "กำลังทำงาน" ปิดการแตะ** (`data-nobusy`) ไม่งั้นนิ้วทะลุไปโดนลิงก์ใต้ลูกศร
7. ใช้ **`dvh` ไม่ใช่ `vh`** (แถบ URL ของมือถือยืด/หด) และเมนูทุกรูปแบบสร้างจาก `NavSet` ชุดเดียว (ไม่มีรายการซ้ำสองที่)

## 3. สถาปัตยกรรม

### 3.1 Desktop: sidebar ที่เลื่อนเฉพาะรายการเมนู

```tsx
{/* จอ ≥ md (768px) */}
<aside className="sticky top-0 hidden h-dvh w-64 shrink-0 flex-col gap-6 border-r border-line bg-surface p-4 md:flex">
  <div className="flex items-center justify-between gap-2">…โลโก้ + กระดิ่ง…</div>     {/* ส่วนหัว: ไม่เลื่อน */}
  <nav aria-label="เมนูหลัก" className="flex-1 space-y-1 overflow-y-auto overscroll-contain">
    {items.map((it) => <NavEntry … />)}                                                 {/* ส่วนเดียวที่เลื่อน */}
  </nav>
  <AccountBox viewer={viewer} />                                                         {/* ส่วนท้าย: ไม่เลื่อน เห็นเสมอ */}
</aside>
```

ทำไมถึงเลื่อนได้ถูกที่:

- `h-dvh` ให้ sidebar สูง **เท่าจอพอดี** (ไม่ใช่สูงตามเนื้อหา) — ไม่มีความสูงที่ตายตัว = ไม่มีอะไรให้ "เกิน"
- `flex-col` + `<nav flex-1 overflow-y-auto>`: nav กินที่ที่เหลือระหว่างหัวกับท้าย; เพราะ `overflow` ไม่ใช่ `visible` ค่า `min-height:auto` ของ flex item จึงเป็น 0 → nav ย่อได้และเลื่อนในตัว (**ถ้าลืม `overflow-y-auto` nav จะดัน sidebar ให้สูงเกินจอ**)
- `sticky top-0` ให้ sidebar อยู่กับที่เมื่อเลื่อนเนื้อหาหน้า — เมนูไม่หลุดจอ
- `overscroll-contain`: ล้อเมาส์ที่เลื่อนจนสุดรายการเมนูแล้ว **ไม่ลามไปเลื่อนทั้งหน้า** (ไม่ใส่ = หน้าด้านขวาเลื่อนตามทันทีที่รายการสุด)
- ผู้ใช้คีย์บอร์ด: Tab ไปเมนูที่ถูกตัด เบราว์เซอร์เลื่อนรายการให้เห็นเอง (ไม่ต้องเขียนโค้ด)

ข้อสังเกต: breakpoint คือ `md` (768px) — **มือถือแนวนอนที่กว้าง ≥ 768px ได้ sidebar** (ไม่ใช่แถบล่าง) และจอแนวนอนเตี้ยมาก ดังนั้นการเลื่อนในตัวของ sidebar สำคัญไม่แพ้แผ่นบนมือถือ
ที่ยังไม่ได้ทำ (ตั้งใจเลือกแบบเรียบง่าย): ลูกศรบอกการเลื่อนบน desktop (ใช้ scrollbar/ล้อเมาส์) และการเลื่อนให้เห็นเมนูที่ active อัตโนมัติ — ถ้าเมนูที่เปิดอยู่อยู่ท้ายรายการยาวมากบนจอเตี้ย อาจอยู่นอกส่วนที่เห็นตอนเปิดหน้า (ทำได้โดยเรียกเหมือนที่ `MoreSheet` ทำ — ดู §3.3)

### 3.2 มือถือ: แถบล่างคงที่ + ปุ่ม "เพิ่มเติม"

```tsx
<nav aria-label="เมนูหลัก" className="fixed inset-x-0 bottom-0 z-40 border-t border-line bg-surface pb-[env(safe-area-inset-bottom)] md:hidden">
  <ul className="flex">
    {primary.map((it) => <li className="flex-1"><BottomItem … /></li>)}   {/* items.slice(0, primaryCount) — 4 รายการ */}
    <li className="flex-1"><button aria-haspopup="dialog" aria-expanded={open} …>… เพิ่มเติม</button></li>
  </ul>
</nav>
<main className="… pb-28 md:pb-10">                                      {/* เว้นที่ท้ายหน้าไม่ให้แถบล่างบังเนื้อหา */}
```

- แถบล่าง **ไม่เลื่อนและไม่ล้น**: 5 ช่องกว้างเท่ากัน (เมนูหลัก `PRIMARY_MAX` = 4) ป้ายกำกับตัดด้วย `truncate`
- เมนูที่เหลือ = `items.slice(primaryCount)` ทั้งหมดอยู่ในแผ่น (ในโค้ดแผ่นแสดง `items` ครบทุกรายการ เพื่อให้ผู้ใช้เห็นเมนูทั้งชุดที่เดียว)
- ถ้าหน้าที่เปิดอยู่เป็นเมนูในแผ่น ปุ่ม "เพิ่มเติม" ไฮไลต์ (`aria-current="true"`) — ผู้ใช้รู้ว่าอยู่ในหมวดนั้น

### 3.3 แผ่น "เพิ่มเติม" ที่เลื่อนได้ + ลูกศรบอก

```tsx
<div className="fixed inset-0 z-50 md:hidden">
  <div className="absolute inset-0 bg-ink/40" onClick={onClose} aria-hidden="true" />        {/* ฉากหลัง: แตะ = ปิด */}
  <div ref={ref} role="dialog" aria-modal="true" aria-label="เมนูเพิ่มเติม" onScroll={measure}
       className="absolute inset-x-0 bottom-0 max-h-[85dvh] overflow-y-auto overscroll-contain rounded-t-3xl bg-surface p-4 pb-[max(1rem,env(safe-area-inset-bottom))]">
    <div className="sticky top-0 z-10 h-0">{canUp && <ปุ่มลูกศรขึ้น/>}</div>     {/* ตัวห่อสูง 0 → ไม่ดันเนื้อหา */}
    …หัวแผ่น + ปุ่มปิด · <nav>รายการเมนู</nav> · AccountBox (ภาษา/ออกจากระบบ)…
    <div className="sticky bottom-0 z-10 h-0">{canDown && <ปุ่มลูกศรลง/>}</div>
  </div>
</div>
```

กลไก:

- **วัดว่าเลื่อนขึ้น/ลงได้ไหม** ด้วยค่าเผื่อ 4px (กันเลขทศนิยมของจอ HiDPI): `canUp = scrollTop > 4` · `canDown = scrollTop + clientHeight < scrollHeight - 4` — วัดตอนเปิด, ตอน `onScroll`, และตอน `resize` (หมุนจอ)
- **ลูกศรเป็น `sticky` ในตัวห่อสูง 0**: ลอยติดขอบบน/ล่างของแผ่นเสมอโดยไม่ดันเนื้อหา; ตัวห่อ `pointer-events-none` (ไล่สีจางไม่บังการแตะรายการข้างใต้) แต่ตัวปุ่ม `pointer-events-auto`
- **กดลูกศร** = `scrollBy({ top: ±max(120, clientHeight × 0.6), behavior: 'smooth' })` — เลื่อนทีละ ~ครึ่งจอ ยังเห็นรายการเดิมต่อเนื่อง ไม่กระโดดข้าม
- **ลูกศรไม่มีเมื่อไม่ต้องใช้** (ไม่ใช่แค่ disabled): บนสุด = ไม่มีลูกศรขึ้น · สุดทาง = ไม่มีลูกศรลง · เมนูพอดีจอ = ไม่มีเลย
- **เปิดแผ่นแล้วเลื่อนไปที่เมนูที่เปิดอยู่**: `scrollTop = cur.offsetTop − clientHeight/2 + cur.offsetHeight/2` (อยู่กลางแผ่น) — ผู้ใช้เห็นทันทีว่าอยู่ตรงไหน และยังมีลูกศรขึ้นบอกว่ามีเมนูด้านบน
- โฟกัสไปที่ปุ่ม/ลิงก์แรกตอนเปิด (`preventScroll`) และคืนโฟกัสให้ปุ่ม "เพิ่มเติม" ตอนปิด; ข้อความลูกศรเป็น `aria-label` สองภาษาจากพจนานุกรม
- **ปุ่มลูกศรใส่ `data-nobusy="true"`** (ดู §5) · ความสูง `85dvh` เหลือฉากหลัง ~15% ให้ผู้ใช้เห็นว่านี่เป็นแผ่นซ้อน แตะนอกแผ่นเพื่อปิดได้

### 3.4 Back / Esc / ลิงก์ในแผ่น (สรุป — รายละเอียดใน BACK-BUTTON-KNOWLEDGE)

แผ่นจอง history 1 รายการตอนเปิด → ปุ่ม Back ของมือถือปิดแผ่น · Esc ปิดแผ่น · แตะลิงก์ในแผ่นถอยรายการก่อนแล้วจึงไปหน้าใหม่ (Back ครั้งเดียวกลับหน้าเดิม) · แผ่นผูกกับ path ที่เปิด (กลับมาหน้าเดิมแผ่นไม่เด้งเอง)

### 3.5 พฤติกรรมตามสถานการณ์

| สถานการณ์                                  | Desktop (sidebar)                                | มือถือ (แผ่น "เพิ่มเติม")                              |
| ------------------------------------------ | ------------------------------------------------ | ------------------------------------------------------ |
| เมนูพอดีจอ                                 | ไม่มีแถบเลื่อน                                   | ไม่มีลูกศร                                             |
| เมนูเกินความสูง                            | เฉพาะรายการเมนูเลื่อน หัว/ท้ายอยู่กับที่         | แผ่นสูง 85% เลื่อนในตัว + ลูกศรลง (ที่บนสุด)           |
| เลื่อนกลางทาง                              | แถบเลื่อนของเบราว์เซอร์                          | ลูกศรขึ้น **และ** ลง                                   |
| เลื่อนสุดทาง                               | ไม่ลามไปเลื่อนทั้งหน้า (`overscroll-contain`)    | เหลือลูกศรขึ้น · ปุ่มออกจากระบบท้ายแผ่นเห็นครบ         |
| เปิดหน้าที่เป็นเมนูท้ายรายการ              | (ยังไม่เลื่อนให้อัตโนมัติ)                       | เปิดแผ่นแล้วเมนูนั้นอยู่กลางแผ่น                       |
| ย่อ/ขยายหน้าต่าง หรือหมุนจอ                | ปรับเองทันที ไม่ต้องโหลดใหม่                     | วัดใหม่ตอน `resize` ลูกศรเปลี่ยนตาม                    |
| กว้าง ≥ 768px แม้เป็นมือถือแนวนอน          | ได้ sidebar                                      | —                                                      |

## 4. กฎที่ห้ามละเมิด

1. **ส่วนที่เลื่อนมีส่วนเดียว** (รายการเมนู) — หัวกับท้าย (บัญชี/ภาษา/ออกจากระบบ) ต้องเห็นเสมอ ห้ามปล่อยให้ทั้ง sidebar/แผ่นเลื่อนรวมกันจนปุ่มท้ายหาย
2. ทุกรายการเมนู **ต้องเข้าถึงได้** บนจอเตี้ยทุกขนาด (เมาส์/ล้อ/แตะ/คีย์บอร์ด) — เมนูที่ "ถูกตัด" ไม่ได้เป็นทางเลือก
3. แผ่นมือถือ **สูงไม่เกิน 85dvh** และต้องบอกชัดว่าเลื่อนได้ (ลูกศร/ขอบจาง) — ห้ามพึ่งแค่ scrollbar ที่มือถือซ่อน
4. ลูกศรบอกการเลื่อน **ต้องแตะได้เสมอ** (`data-nobusy`) และตัวห่อต้อง `pointer-events-none` เฉพาะส่วนไล่สี
5. ใช้ **`dvh`** (ไม่ใช่ `vh`) และเว้น `env(safe-area-inset-bottom)` ที่แถบล่าง/แผ่น
6. `overscroll-contain` ที่ส่วนที่เลื่อนในตัวทั้งสองแบบ
7. รายการเมนูมาจาก `NavSet` ชุดเดียว (`nav.ts`) — **ห้ามเขียนลิงก์เมนูซ้ำ**ใน sidebar/แผ่น; ข้อความเมนูและ aria-label มาจากพจนานุกรมสองภาษา
8. ห้ามแก้ความสูงเมนูเป็นค่าตายตัว (px) — ให้ flex + `dvh` จัดการ

## 5. บทเรียนจากของจริง

| เกิดอะไร                                                                                  | สาเหตุราก                                                                                                                         | แก้อย่างไร                                                                                                           |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| เลื่อนล้อเมาส์จนสุดรายการเมนู แล้ว **ทั้งหน้าเลื่อนต่อ** (เจอตอนเขียนเทสจอเตี้ย)           | scroll chaining: ส่วนที่เลื่อนในตัวสุดทางแล้ว เบราว์เซอร์ส่งต่อให้ตัวแม่                                                           | `overscroll-contain` ที่ `<nav>` ของ sidebar และแผ่น "เพิ่มเติม"                                                      |
| **แตะลูกศรเลื่อนแล้วนิ้วทะลุไปกดลิงก์ข้างใต้** (เทสเจอว่าเปิดหน้า "ความเป็นส่วนตัว" แทน)  | `BusyFeedback` ใส่ `data-busy` ให้ปุ่มที่เพิ่งกดเมื่อมี server function ค้าง และ CSS `[data-busy]{pointer-events:none}` กับลูกศร   | ใส่ `data-nobusy="true"` ที่ลูกศรทั้งสอง (BusyFeedback ข้ามปุ่มที่มี attribute นี้)                                  |
| เทส e2e กดลูกศร (`locator.click`) แล้วค้าง/แผ่นกระโดดไปสุด                                | Playwright เรียก `scrollIntoView` กับ element แบบ `sticky` → เลื่อนแผ่นไปตำแหน่งธรรมชาติ (ท้ายเนื้อหา) แล้วลูกศรหายกลางคัน        | เทสแตะตำแหน่งจริง `page.touchscreen.tap(x, y)` จาก `boundingBox()` (เหมือนนิ้วผู้ใช้)                               |
| nav ไม่เลื่อน กลับไปดัน sidebar ให้สูงเกินจอ                                              | ลืม `overflow-y-auto` หรือ aside ไม่มีความสูงตายตัว (`h-dvh`)                                                                     | `aside: sticky top-0 h-dvh flex-col` + `nav: flex-1 overflow-y-auto`                                                 |
| แผ่นสูงเกินจอบนมือถือที่มีแถบ URL                                                        | ใช้ `vh` (นับรวมแถบ URL ที่ซ่อนอยู่)                                                                                              | ใช้ `dvh`                                                                                                            |
| ผู้ใช้เปิดแผ่นแล้วไม่เห็นว่าตัวเองอยู่เมนูไหน (เมนูที่เปิดอยู่อยู่ท้ายรายการ)             | แผ่นเปิดที่บนสุดเสมอ                                                                                                              | เปิดแล้วเลื่อนให้เมนูที่เปิดอยู่อยู่กลางแผ่น (+ ลูกศรขึ้นบอกว่ายังมีด้านบน)                                          |
| ลูกศรขึ้นโผล่ทั้งที่อยู่บนสุด (กะพริบ) บนจอ HiDPI                                         | `scrollTop` เป็นเลขทศนิยม เทียบกับ 0 ตรง ๆ                                                                                        | ค่าเผื่อ 4px ทั้งสองทาง                                                                                              |
| กดลิงก์ในแผ่นแล้ว Back ต้องกดสองครั้ง                                                     | แผ่นจอง history 1 รายการ แต่ลิงก์ push ซ้อน                                                                                       | ถอยรายการของแผ่นก่อนแล้วค่อยไปหน้าใหม่ (BACK-BUTTON-KNOWLEDGE)                                                       |

## 6. ลอกไปใช้อย่างไร

1. ทำรายการเมนูชุดเดียวต่อบทบาท (`NavSet = { items, primaryCount }`) — sidebar แสดง `items` ทั้งหมด · แถบล่างแสดง `items.slice(0, primaryCount)` + ปุ่ม "เพิ่มเติม" · แผ่นแสดง `items` (หรือส่วนที่เหลือ) ทั้งชุด
2. Desktop: `aside = sticky top-0 h-dvh flex-col` · ส่วนหัวไม่หด · `nav = flex-1 overflow-y-auto overscroll-contain` · ส่วนท้ายคงที่
3. มือถือ: แถบล่าง `fixed bottom-0` + `safe-area` · เนื้อหา `pb-28` · แผ่น `fixed inset-0` + ฉากหลัง + แผงล่าง `max-h-[85dvh] overflow-y-auto overscroll-contain`
4. ลูกศร: ตัวห่อ `sticky top-0/bottom-0 h-0` + `pointer-events-none` · ปุ่ม `pointer-events-auto` + `data-nobusy` · วัด `canUp/canDown` (เผื่อ 4px) ตอนเปิด/scroll/resize · กด = `scrollBy` ~60% ของความสูง smooth
5. เปิดแผ่นแล้วเลื่อนไปที่เมนูที่ active · จัดการโฟกัส · Esc · ปุ่ม Back (ดู BACK-BUTTON-KNOWLEDGE)
6. ถ้ามีตัวบอกสถานะ "กำลังทำงาน" ระดับแอปที่ปิดการแตะปุ่ม ให้ยกเว้นปุ่มที่ไม่ใช่การกระทำ (ลูกศรเลื่อน/ปุ่มเปิดเมนู)
7. เทส: **จอเตี้ย** เพื่อให้เมนูยาวเกินจอเสมอ — desktop 1280×420 (nav `scrollHeight > clientHeight`, `overflow-y:auto`, ปุ่มท้าย sidebar อยู่ในจอ, ล้อเมาส์เลื่อนถึงเมนูสุดท้ายโดย `window.scrollY` ไม่ขยับ, โฟกัสเมนูสุดท้ายแล้วเห็น, ย่อ/ขยายจอแล้วปรับเอง) · มือถือ 390×520 (แถบล่างติดขอบ 5 ช่อง, แผ่นสูง ≤ 85% ติดขอบล่าง, ลูกศรขึ้น/ลงตามตำแหน่ง, เลื่อนถึงปุ่มออกจากระบบ, Esc ปิดแล้วโฟกัสกลับ, จอสูงพอ = ไม่มีลูกศร) และกรณีเปิดแล้วเมนูที่ active อยู่ในส่วนที่เห็น
