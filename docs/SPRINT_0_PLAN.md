แสดงคำเตือนข้อมูลสมมติชัดเจน ไม่มีบัญชี ข้อมูลส่วนบุคคล ผู้ให้บริการค้นหาจริง การวิเคราะห์ผู้ใช้

ชิ้นงานนี้เป็นตัวเลือกสำหรับ REQ-01/04/13 และ AC-01/14 ที่เจ้าของอ้าง แต่ยังตรวจความหมายไม่ได้

## แผน 6 ระยะ: Phase 0–5

ระยะเป็นลำดับงาน ส่วน PR คือชุดเปลี่ยนแปลงสำหรับทบทวน อาจแบ่งหลาย PR ต่อระยะได้
ประมาณการเดิมเป็นคน-วันของผู้พัฒนา ไม่รวมเวลารอเจ้าของ งานกฎหมาย/คำแปลภายนอก
การจัดซื้อ และรับพันธมิตรจริง เป็นช่วงประมาณการ ไม่ใช่วันส่งมอบ และไม่มีระยะใดได้รับอนุมัติเพียงเพราะอยู่ในตาราง

| ระยะ | ผลงานและสิ่งที่ต้องมีมาก่อน | เกณฑ์ตรวจรับ/จุดตรวจ | ประมาณการ |
| --- | --- | --- | --- |
| Phase 0 วางแผน | ตรวจคลังงาน ทะเบียนการตัดสินใจ ข้อเสนอสถาปัตยกรรม/เทคโนโลยี และแผน พร้อมระบุเอกสารขาด | ตรวจลิงก์/รหัสและแยก C/P/G; ได้แผนชั่วคราวแล้ว แต่ยังต้องเทียบต้นฉบับและให้เจ้าของเลือก | 0.5–1 คน-วัน |
| Phase 1 ตั้งโครงโครงการ | หลัง LEG-G-01: ล็อกรุ่นเสถียรของแพ็กเกจ/runtime, lockfile, โครงภาษา สคริปต์จริง CI การตรวจข้อมูลสมมติ และเครื่องมือทดสอบ; รักษาเอกสาร | S0-01, S0-02; LEG-G-02; ห้ามอ้างสำเร็จด้วยชุดทดสอบว่าง | 1–2 คน-วัน |

ทุก PR ต้องระบุไฟล์เปลี่ยน คำสั่งที่รันจริง จำนวนทดสอบ รายการข้าม ข้อจำกัด และช่องว่าง MVP
ห้ามถือว่าคำสั่งที่วางแผนไว้ผ่านแล้ว

## ชุดข้อมูลสมมติ

ใช้องค์กรแต่งขึ้นและลิงก์ `.invalid` ไม่มีชื่อ ผู้ติดต่อ คำรับรอง โลโก้ ที่อยู่ หรือเรื่องราวบุคคลจริง
ติดป้ายสมมติทุกระเบียน อย่างน้อยมี: รายการปัจจุบันสองรายการต่างพื้นที่/กลุ่มผู้รับประโยชน์;
หมดอายุพอดี ณ เวลาทดสอบ; หมดอายุแล้ว; ระงับแต่เงื่อนไขอื่นยังเป็นปัจจุบัน; หลักฐานขาด;
ตรวจในอนาคต; คำแปลขาดสำหรับทดสอบไม่ผ่าน; ข้อความแปลยาว; HTML/URL โจมตี;
ข้อมูลว่าง; รหัสไม่รู้จัก; และคำค้นที่ไม่ตรงรายการใด ใช้เวลาตรึง รหัสคงที่ ลำดับคงที่
แยกข้อมูลที่จงใจผิดจากข้อมูลตัวอย่างปกติ ระยะหลังเพิ่มองค์กร A/B บทบาท วงจรยินยอม
และเหตุการณ์ผลลัพธ์สมมติ โดยไม่จำลองกระบวนการข้อมูลส่วนบุคคลผู้เยาว์

## คำสั่งที่วางแผนให้มีหลังตั้งโครงการ — ยังไม่มีและยังไม่ได้รัน

ทำงานใน `/workspace/global-opportunity-os` ทุกคำสั่ง Phase 1 ต้องสร้าง package.json,
รุ่นที่ล็อก, package-lock.json, tsconfig, การตั้งค่า ESLint/Vitest/Playwright และชุดทดสอบจริงก่อน
ใช้ checkout แยกที่มีอยู่ ไม่ต้องสร้าง worktree

```sh
npm ci
npx --no-install playwright install --with-deps chromium
npm run typecheck
npm run lint
npm run test:unit
npm run build
npm run test:e2e
npm run test:a11y
npm run dev -- --hostname 127.0.0.1 --port 3000
```

สัญญาสคริปต์ที่เสนอ: `typecheck` = `tsc --noEmit`; `lint` = `eslint .`;
`test:unit` = `vitest run`; `build` = `next build`; `dev` = `next dev`;
`start` = `next start`; `test:e2e` = `playwright test --project=chromium`;
`test:a11y` = `playwright test --project=chromium tests/a11y`
Phase 1 ต้องตั้ง Playwright webServer ให้ build/เปิดเซิร์ฟเวอร์ production ที่ 127.0.0.1:3000
และรอพร้อมใช้งาน แยกการจับคู่ชุดทดสอบพฤติกรรม/การเข้าถึง ตรวจจำนวนมากกว่าศูนย์
เริ่ม CI ด้วยหนึ่ง worker ตรวจด้วยคนหลังเปิด dev ไม่สัญญาลิงก์ดูตัวอย่าง localhost
build ไม่แทน lint การติดตั้งเบราว์เซอร์อาจต้องมีแพ็กเกจระบบ/สิทธิ์เครือข่าย ต้องวินิจฉัยเมื่อถึงเวลา
Firefox/WebKit และอุปกรณ์/ภาษาอื่นเป็นส่วนเสริมหลัง Chromium ไม่ใช่สิ่งแทนการตรวจพื้นฐาน
ยังไม่กำหนดคำสั่งทดสอบฐานข้อมูลจนกว่าจะอนุมัติและตั้งเครื่องมือฐานข้อมูล/ตัวตน/ย้ายโครงสร้างจริง
