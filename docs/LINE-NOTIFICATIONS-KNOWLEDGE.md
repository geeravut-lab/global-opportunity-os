## 1. ปัญหาที่แก้

- ทุกเหตุการณ์สำคัญ (ชำระเงินผ่าน/ไม่ผ่าน, ออเดอร์เปลี่ยนสถานะ, มีคนแจ้งโอน, สต็อกใกล้หมดอายุ, ถึงเวลานัด) ต้องไปถึงคนที่เกี่ยวข้อง **ทั้งในแอปและบน LINE**
- LINE Messaging API มี **โควตาข้อความต่อเดือน** (แผนฟรีน้อยมาก), ล่มได้, token หมดอายุได้, ผู้ใช้บล็อกได้ — การส่งต้องไม่ทำให้งานของผู้ใช้ช้าหรือล้ม
- ข้อความที่ขึ้นบนหน้าจอล็อกต้องเข้าใจได้เองโดยไม่ต้องเปิดแอป และต้องไม่เปิดเผยข้อมูลอ่อนไหว

## 2. สรุปสั้น

1. **ผู้เขียนแจ้งเตือนมีที่เดียว**: `notifyUser()` / `tell()` / `tellMany()` / `notifyAdmins()` / `notifyBranchManagers()` / `notifyPharmacists()`
   → เขียนกล่องแจ้งเตือนในแอป **และ** แถวคิว LINE จากที่เดียวกัน — **ไม่เคย throw** (เหตุการณ์เกิดไปแล้ว ข้อความพลาดต้องไม่ทำให้งานหลักล้ม)
2. **คิวก่อน ส่งทีหลัง**: งานของผู้ใช้แค่เขียนคิว; tick ทุก 10 นาทีเป็นคนส่ง (หรือ flush หลังตอบ response ถ้าเปิด `NOTIFY_LINE_IMMEDIATE=1`)
3. **dedupe key** (unique ต่อคน) ทั้งในกล่องและคิว — เหตุการณ์เดียวบอกครั้งเดียว แม้กฎรันทุก 10 นาที
4. **ผู้ใช้ควบคุมเอง**: ข้อความบริการ (ผลการชำระเงิน แพ็กเกจใกล้หมด) เปิดเป็นค่าเริ่มต้นเมื่อผูก LINE; การเตือนนิสัย **ปิดเป็นค่าเริ่มต้น** (ต้องเลือกเปิด)
5. **โควตาของเราเอง** ต่ำกว่าของ LINE: เพดานรายเดือน + **ส่วนสำรอง** สำหรับข้อความด่วน (ข้อความเตือนหยุดก่อนถึงเพดาน `reserve` ข้อความ)
6. **ตาราง error ชัดเจน**: 200/409 = ส่งแล้ว · 401/403 = หยุดทั้งระบบ 6 ชม. + แจ้งแอดมิน · 400 = ผู้รับบล็อก ไม่ลองซ้ำ · 429 monthly = หยุดรอบนี้ · 5xx/เครือข่าย = ลองใหม่สูงสุด 3 ครั้ง
7. **`X-Line-Retry-Key` = id ของแถวคิว** → ลองซ้ำ/ส่งซ้อนจากสองทาง LINE ไม่ส่งซ้ำ (ตอบ 409 ซึ่งถือว่าส่งแล้ว)
8. **การ์ด Flex**: หัวเรื่อง + บรรทัด "ป้าย: ค่า" + ปุ่มเปิดแอป; `altText` (ที่โชว์บนหน้าจอล็อก) มีรายละเอียดครบ; ปุ่มเปิดในเบราว์เซอร์ของเครื่อง (`openExternalBrowser=1`)
9. **ข้อความในภาษาของผู้รับ** (`dictFor(userId)`) และชื่อแอปตามที่แอดมินตั้ง

## 3. โครงที่ใช้

### 3.1 ตาราง

| ตาราง                   | หน้าที่                                                                                                       | สิทธิ์                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `app_notifications`     | กล่องแจ้งเตือนในแอป (kind, title, body, href, read_at, dedupe_key)                                            | ผู้ใช้ select/delete ของตัวเอง, update เฉพาะคอลัมน์ `read_at` |
| `notification_queue`    | ข้อความรอส่ง LINE — **คัดลอก** title/body/href (อยู่รอดแม้กล่องถูกล้าง), urgent, status, attempts, last_error | service role เท่านั้น                                         |
| `notification_prefs`    | สวิตช์ของผู้ใช้: `line_transactional` (เริ่ม true), `line_reminders` (เริ่ม false)                            | ผู้ใช้ insert/update คอลัมน์ของตัวเอง                         |
| `notification_settings` | แถวเดียว: `line_monthly_cap` (200), `line_reserve` (20), `halted_until`, `halted_reason`                      | service role                                                  |
| `line_links`            | user ↔ LINE user id (`line_sub`)                                                                              | —                                                             |

- `kind` เป็นข้อความอิสระ (ไม่ใช่ CHECK รายการ) — รายการที่โตขึ้นเรื่อย ๆ ใน CHECK จะปฏิเสธชนิดใหม่เงียบ ๆ
- `href` ต้องเป็น path ภายใน (`/…` ไม่ใช่ `//…`) ทั้งใน CHECK และ `safeHref()`
- index: `notification_queue (user_id, dedupe_key) unique where dedupe_key is not null`, `(created_at) where status='queued'`, `(sent_at) where status='sent'`

### 3.2 รูปแบบข้อความเดียว (`Notice`)

```ts
interface Notice {
  kind: string;
  title: string;
  body: string; // noticeBody(summary, [["ออเดอร์", "RS-000492"], ["ยอด", "340 บาท"]]) → "สรุป\nออเดอร์: RS-000492\nยอด: 340 บาท"
  href: string | null; // path ในแอป
  dedupeKey?: string; // ครั้งเดียว: id ของเหตุการณ์ · เกิดซ้ำได้: ใส่ Date.now()
  category: "transactional" | "reminder";
  urgent?: boolean; // ผลที่ผู้ใช้รออยู่: ใช้ส่วนสำรองได้
}
```

ข้อความเป็น **plain text บรรทัด "ป้าย: ค่า"** ใช้ร่วมกันทั้งกล่องในแอป การ์ด LINE และ altText (`parseNoticeBody` นับเป็นป้ายเฉพาะส่วนหน้า ": " ที่ยาว ≤ 24 ตัว)
ตัวสร้างข้อความอยู่รวมกัน: `messages.ts` (เงิน ร้านค้า), `events.ts` (เหตุการณ์อื่น), `telepharmacy/notices.ts`, `ekyc/notices.ts`, `stock/notices.ts`

### 3.3 `notifyUser(userId, notice)`

1. insert `app_notifications` — **23505 (key ซ้ำ) = บอกไปแล้ว จบ** ไม่เขียนคิว
2. อ่าน `line_links` และ `notification_prefs` พร้อมกัน → อนุญาตไหม (reminder ต้องเปิดเอง, transactional เปิดเป็นค่าเริ่มต้น)
3. insert `notification_queue` (คัดลอกข้อความ) — 23505 ไม่ใช่ error
4. ข้อความบริการ → `scheduleLineFlush(userId)` (ส่งหลังตอบ response ถ้าเปิดไว้)
5. ทั้งหมดอยู่ใน try/catch → log แล้วคืน false

`notifyAdmins(builder, exceptUserId?)` สร้างข้อความ **ในภาษาของแอดมินแต่ละคน** — ตามกฎเงิน (owner 2026-10-13) การแจ้งโอนทุกครั้งไปถึงแอดมิน **ทุกคน รวมคนที่ทำเอง** และ key มีเวลาอยู่ด้วย

### 3.4 ผู้ส่ง (`deliverQueued`, pure + dependency injection)

```
ไม่มี token                      → หยุด (no_token)
halted_until ยังไม่ถึง            → หยุด (halted)
used = จำนวนที่ส่งแล้วเดือนนี้ (นับจากคิวของเรา — ตัวนับของ LINE อัปเดตช้า)
rows = แถว queued 20 แถว เรียง urgent ก่อน แล้วเก่าก่อน
ทุกแถว:
  limit = urgent ? cap : cap - reserve;  used >= limit → หยุด (quota)   [urgent มาก่อน จึงไม่มี urgent ค้างข้างหลัง]
  ไม่ได้ผูก LINE                  → skipped (not_linked)
  push(to, row, retryKey = row.id)
    200 / 409                     → sent (409 = LINE รับ retry key นี้ไปแล้ว)
    401 / 403                     → halt 6 ชม. + log ให้แอดมินเห็น → หยุดทั้งรอบ (auth)
    400                           → blocked (ผู้รับบล็อก/ไม่ได้เป็นเพื่อน) ไม่ลองซ้ำ
    429 + "monthly"               → skipped (monthly_quota) + log → หยุด
    อื่น ๆ (5xx, 429 อื่น, network) → attempts+1; ครบ 3 → failed, ไม่งั้นรอรอบหน้า (retrying)
```

`pushToLine`: `POST https://api.line.me/v2/bot/message/push` พร้อม `Authorization: Bearer <token>`, `X-Line-Retry-Key`, timeout 8 วินาที, **ไม่ throw** (เครือข่ายล่ม = status 0)

dependency ทั้งหมด (`settings`, `sentThisMonth`, `fetchDue`, `lineUserIds`, `push`, `update`, `halt`, `log`) ถูกส่งเข้ามา → เทสทุกแถวของตาราง error ได้โดยไม่แตะ LINE จริง

### 3.5 ส่งทันที (`flush.ts`)

- `NOTIFY_LINE_IMMEDIATE=1`: หลังเขียนคิวข้อความบริการ จัดตารางให้ `after()` (หลังตอบ response) ส่งคิวของคนนั้น
- หลายแจ้งเตือนในคำขอเดียว (ออเดอร์จ่ายแล้ว → แอดมินทุกคน) รวมเป็น flush เดียว
- ไม่มี request ให้เกาะ (ตอนรันใน tick) → ไม่ทำอะไร tick ส่งเอง
- แข่งกับ tick ได้อย่างปลอดภัยเพราะ retry key เดียวกัน
- **ห้ามเปิดในสภาพแวดล้อมเทส/อัดคู่มือ** (จะส่งถึงมือถือแอดมินจริง)

### 3.6 การ์ด Flex (`buildLineMessage`)

- bubble: หัวเรื่องตัวหนาสีแบรนด์ (≤ 100 ตัว) → บรรทัด "ป้าย | ค่า" สูงสุด 8 บรรทัด (ป้าย ≤ 24, ค่า ≤ 120) → ปุ่มหลักสี coral "เปิดแอป"
- `altText` ≤ 400 ตัว = หัวเรื่อง — ป้าย ค่า · ป้าย ค่า (สิ่งที่โชว์บนหน้าจอล็อก/รายการแชต)
- ปุ่ม: `appOpenUrl(base, href)` = URL เต็ม + `openExternalBrowser=1` → เปิดในเบราว์เซอร์ของเครื่อง (เบราว์เซอร์ในแอป LINE ขอให้ล็อกอินใหม่และใช้บางฟีเจอร์ไม่ได้ จึง **ไม่ใช้ LIFF**)
- ตัดข้อความยาวด้วย "…" ทุกช่อง (LINE ปฏิเสธทั้งข้อความถ้าเกินขีด)

### 3.7 ผูกบัญชี LINE

- ผู้ใช้ผูก LINE จากหน้าตั้งค่า; บัญชี LINE หนึ่งผูกได้กับผู้ใช้เดียว — ถ้าผูกกับคนอื่นอยู่ บอกวิธีแก้ตามชนิดของบัญชีนั้น **ไม่ยึด/ลบจากบัญชีอื่นอัตโนมัติ** (`classifyLinkConflict`)
- บัญชีที่เข้าด้วย LINE อย่างเดียวถอด LINE ไม่ได้ (จะไม่มีทางเข้า)

### 3.8 หน้าแอดมิน (ส่วน LINE ใน `/admin/rules`)

แสดงว่าเดือนนี้ส่งไปแล้วเท่าไรจากเพดาน, ตั้งเพดานรายเดือนและส่วนสำรอง (`reserve ≤ cap`), เห็นสถานะ "หยุดส่ง" พร้อมเวลาและเหตุผล และติ๊ก "ส่งต่อ" หลังแก้ token แล้ว; สรุปของแต่ละรอบ (ส่งได้ / ล้มเหลว / ถูกบล็อก / ข้าม / รอลองใหม่) อยู่ในรายการรอบล่าสุดของกฎอัตโนมัติ; error ของ LINE ถูกบันทึกใน `ai_events` (provider `line`) ให้เห็นในหน้า `/admin/ai` — ทุกการแก้ audit `settings.line_limits`

## 4. กฎที่ห้ามละเมิด

1. ฟีเจอร์ห้ามเรียก LINE API เอง — ผ่าน `notifyUser`/`tell` เท่านั้น
2. ห้ามส่ง LINE แบบรอผลในคำขอของผู้ใช้
3. ทุกการเปลี่ยนสถานะที่มีคนรออยู่ = แจ้งเตือนถึงทุกฝ่ายที่เกี่ยวข้อง (ได้/เสียสิทธิ์, เงิน, ออเดอร์, นัด)
4. เหตุการณ์ครั้งเดียวใช้ key จาก id; เหตุการณ์ที่เกิดซ้ำได้ใส่เวลาใน key
5. ข้อความที่ออกนอกแอป **ห้ามมี** หัวข้อการปรึกษา คำแนะนำ ชื่อยา ค่าผลแล็บ หรือข้อมูลอ่อนไหว — บอกแค่ว่ามีเรื่อง และให้เปิดแอปดู
6. href เป็น path ภายในเท่านั้น
7. การเตือนนิสัยต้องเป็น opt-in; ข้อความบริการปิดได้
8. ข้อความด่วนต้องมีโควตาสำรองเสมอ

| ลูกค้ากดปุ่มในการ์ดแล้วต้องล็อกอินใหม่                            | เปิดในเบราว์เซอร์ของ LINE      | `openExternalBrowser=1`                                                   |

| ล้างกล่องแจ้งเตือนแล้วคิว LINE ที่ยังไม่ส่งหายข้อความ             | คิวอ้างข้อความจากกล่อง         | คัดลอกข้อความลงคิว                                                        |
| แจ้งเตือนช้าจนผู้ใช้คิดว่าระบบค้าง (รอ tick 10 นาที)              | ส่งเฉพาะใน tick                | flush หลัง response สำหรับข้อความบริการ (เปิดด้วย env)                    |
| เทสอัตโนมัติส่ง LINE ถึงแอดมินจริง                                | เทสสร้างเหตุการณ์ที่แจ้งแอดมิน | ไม่เปิด `NOTIFY_LINE_IMMEDIATE` ในเทส + `removeAdminNoticesSince` หลังเทส |

## 6. ลอกไปใช้อย่างไร

1. ตาราง 4 ตัว + `line_links` + RLS ตาม §3.1
2. `Notice` + `noticeBody` / `parseNoticeBody` / `safeHref`
3. `notifyUser` (กล่อง → อนุญาต → คิว, never throw) + ตัวช่วยส่งหาแอดมิน/ทีม ในภาษาของแต่ละคน
4. `deliverQueued` แบบ dependency injection + `pushToLine` + `lineDeps` จริง
5. `buildLineMessage` (Flex + altText + `openExternalBrowser=1`)
6. ส่งใน tick (`docs/AUTOMATION-RULES-KNOWLEDGE.md`) + flush ทันที (ถ้าต้องการ)
7. หน้าผู้ใช้: กล่องแจ้งเตือน + สวิตช์ LINE; หน้าแอดมิน: เพดาน/สำรอง/ส่งต่อ/ทดสอบ
8. เทส: ทุกแถวของตาราง error (`deliverQueued` กับ deps ปลอม), urgent กับเพดาน, `buildLineMessage` (ตัดความยาว, altText, URL), `parseNoticeBody` (ประโยคที่มี ":"), flush รวมเป็นครั้งเดียว
