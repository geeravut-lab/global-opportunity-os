# ข้อเสนอสถาปัตยกรรม โครงสร้างข้อมูล และสิทธิ์ — LEG-P-04

ขอบเขตชิ้นงานแรกอนุมัติและทำตาม LEG-C-07 แล้ว ส่วนแบบจำลองข้อมูล/สิทธิ์ของระยะหลังยังเป็นข้อเสนอ
ไม่มีฐานข้อมูล RLS หรือการยืนยันตัวตนที่นำมาใช้จริง ดูรายละเอียดที่ทำแล้วใน IMPLEMENTATION_REPORT.md
ยึด LEG-C-01 ถึง LEG-C-09 ใน DECISIONS.md ชิ้นงานแรกไม่มีข้อมูลรายบุคคลของผู้รับประโยชน์หรือกระบวนการผู้เยาว์

## ขอบเขตชิ้นงานแรก

เบราว์เซอร์ → หน้ารายการ/รายละเอียดตามภาษา → ชุดข้อมูลสมมติที่ตรวจรูปแบบแล้ว
กำหนดเส้นทางภาษาและพจนานุกรมในโครงการ ใช้โมดูลกฎตัวกรอง/เผยแพร่ร่วมกันระหว่างรายการกับรายละเอียด
ไม่มีฐานข้อมูล บัญชี แบบฟอร์มเก็บข้อมูลส่วนบุคคล คุกกี้ การวิเคราะห์ผู้ใช้ ข้อความภายนอก API พันธมิตร หรือข้ออ้างข้อมูลจริง
เก็บไฟล์ประกอบในโครงการ แยกตัวอ่านข้อมูลเพื่อเปลี่ยนแหล่งข้อมูลภายหลังโดยไม่เผยโมเดลเคสส่วนตัวสู่หน้าสาธารณะ
แสดงคำเตือนว่าเป็นข้อมูลสมมติเสมอ แสดงข้อความที่ไม่น่าเชื่อถือโดย escape ไม่รัน HTML ตามอำเภอใจ
ลิงก์ตัวอย่างใช้ example.invalid และต้องไม่ส่งต่อเคสจริง

เขตข้อมูลรายการที่เสนอ:
`id`, `tenant_id`, `slug`, `title_by_locale`, `description_by_locale`,
`service_categories`, `beneficiary_groups`, `coverage_regions`, `eligibility_text`,
`accessibility_notes`, `status`, `verified_at`, `verification_expires_at`,
`source_label`, `synthetic=true`
ใช้รหัสคงที่ เวลา UTC ที่มีเขตเวลา รหัสภาษา BCP 47 และรหัสประเทศ/พื้นที่
ข้อความอิสระต้องไม่ตัดสินสิทธิ์รายบุคคลหรือบังคับเปิดเผยคุณลักษณะอ่อนไหว

กฎสถานะ: รายการที่แสดงเป็นปัจจุบันและมีปุ่มตัวอย่างต้องเผยแพร่ชัดเจน มีหลักฐานตรวจแล้ว
และ `verified_at <= now < verification_expires_at` หากหลักฐาน/เวลาไม่ครบหรือผิด ให้ปฏิเสธไว้ก่อน
การระงับมีผลเหนือสถานะอื่น ตัวอย่างหมดอายุ/ระงับแสดงสถานะและคำอธิบายได้ แต่ไม่มีปุ่มส่งต่อ
มีตัวกรองสถานะให้ตรวจตัวอย่างเหล่านี้ ผลว่างอธิบายวิธีล้างตัวกรอง ห้ามติดป้ายพันธมิตรจริงที่ตรวจแล้ว
ให้ข้อมูลสมมติ รหัสที่ไม่รู้จักแสดง 404 ที่เข้าถึงได้ ตรึงเวลาในทดสอบและตรวจจุดเท่ากับวันหมดอายุ
การเผยแพร่จริงและการล้างแคชต้องผ่าน LEG-P-05; เว็บสถิตอย่างเดียวไม่รับรองการระงับทันที
ห้ามนำแคชตัวอย่างไปใช้กับการตรวจสิทธิ์/ข้อมูลจริงโดยไม่ออกแบบใหม่

## ขอบเขต MVP ระยะถัดไป — ไม่ใช่งานชิ้นแรก

Navigator ช่วยนำทางตามบริการ/หมวด/พื้นที่อย่างอธิบายได้ ไม่สร้างโปรไฟล์อ่อนไหวหรือตัดสินสิทธิ์อัตโนมัติ
การส่งต่อ/เคสต้องยืนยันตัวตน มีความยินยอมเฉพาะผู้รับ และตรวจสิทธิ์ตามองค์กร (tenant)
รายงานผลใช้ข้อมูลรวมพร้อมที่มา ไม่เผยประวัติผู้รับประโยชน์ เลื่อนระบบตลาดงาน การชำระเงิน
การส่งมอบการเรียนรู้ และกระบวนการข้อมูลส่วนบุคคลผู้เยาว์ออกไป ยังไม่เลือกตัวตน โฮสต์ ORM หรือบริการเสียเงิน

| องค์ประกอบที่เสนอ | ความสัมพันธ์และข้อกำหนดขั้นต่ำ |
| --- | --- |
| Tenant / Membership | รหัสองค์กร; สมาชิกผูกผู้ใช้ที่ยืนยันตัวตน องค์กร และบทบาทแบบไม่ซ้ำ; ถอนสมาชิกต้องเสียสิทธิ์ทันที ห้ามเชื่อ tenant ID จากผู้ใช้เพียงอย่างเดียว |
| DirectoryEntry / VerificationEvidence | รายการเป็นขององค์กร; ข้อมูลสาธารณะเลือกเฉพาะฟิลด์ที่อนุญาต หลักฐานส่วนตัวเก็บผู้ตรวจ แหล่งที่มา เวลาและวันหมดอายุ; ไม่มี URL ไฟล์แนบที่เข้าถึงได้โดยไร้ข้อจำกัด |
| Referral / Case | องค์กรต้นทาง/ผู้รับ สถานะ และรหัสอ้างอิงบุคคลเท่าที่จำเป็นตามวัตถุประสงค์; ใช้ composite foreign key ที่รวมองค์กร ป้องกันความสัมพันธ์ข้ามองค์กร การแบ่งปันต้องมีสิทธิ์เฉพาะ ไม่เปิดให้พันธมิตรทุกแห่ง |
| Consent | องค์กร รหัสบุคคล วัตถุประสงค์ ผู้รับ รุ่นประกาศ เวลายินยอม/หมดอายุ/ถอน; การส่งต่ออ้างความยินยอมที่ตรงกันและตรวจอีกครั้ง ณ ธุรกรรมส่ง |
| AuditEvent | ผู้กระทำ องค์กร การกระทำ รหัสวัตถุ เวลา; เก็บข้อมูลประกอบขั้นต่ำ ไม่บันทึกเนื้อหาส่วนตัวหรือความลับ บทบาทแอปเพิ่มได้แต่แก้ย้อนหลังไม่ได้ |
| ImpactEvent / Aggregate | ประเภทเหตุการณ์ กุญแจป้องกันซ้ำ และที่มา; จำกัดสิทธิ์ข้อมูลต้นทาง สรุปสาธารณะโดยซ่อนกลุ่มขนาดเล็กตามเกณฑ์ที่ทบทวน การสร้างรายการส่งต่อไม่ใช่ผลสำเร็จ |

ข้อมูลจริง ระยะเก็บ ข้อยกเว้นการลบ และฐานกฎหมายต้องให้เจ้าของ/ผู้เชี่ยวชาญทบทวนก่อนพัฒนา
ไม่เก็บเอกสาร สุขภาพ พิกัดละเอียด หรืออายุโดยปริยาย ทดสอบการถอนพร้อมการส่งและงานในคิว:
ตรวจความยินยอมก่อนส่ง ยกเลิกงานที่ยังไม่ส่ง ยกเลิกการเข้าถึงต่อไป และเก็บเฉพาะข้อมูลตรวจสอบที่มีเหตุผล
ข้อมูลที่เปิดเผยแก่ผู้รับแล้วเรียกคืนไม่ได้ทั้งหมด ต้องระบุข้อจำกัดในข้อตกลงผู้รับและประกาศแก่ผู้ใช้

## ตารางสิทธิ์ที่เสนอ

| ผู้กระทำ | ไดเรกทอรีสาธารณะ | เขียนรายการ/หลักฐาน | ส่งต่อ/เคส | ความยินยอม/ประวัติตรวจสอบ |
| --- | --- | --- | --- | --- |
| ผู้ไม่เข้าสู่ระบบ | เฉพาะฟิลด์เผยแพร่ที่อนุญาต | ปฏิเสธ | ปฏิเสธ | ปฏิเสธ |
| ผู้แก้ไขขององค์กร | ข้อมูลสาธารณะ | ร่างในองค์กรตนเอง; เผยแพร่เองไม่ได้ | ปฏิเสธโดยปริยาย | ข้อมูลการกระทำของตนตามสิทธิ์เท่านั้น |
| ผู้ตรวจที่ได้รับมอบหมาย | ข้อมูลสาธารณะ | ตรวจ/เผยแพร่/ระงับในองค์กรตน หลักฐานเฉพาะที่มอบหมาย | ปฏิเสธ | เพิ่มประวัติการตรวจเท่านั้น |
| ผู้ดูแลเคสที่ได้รับมอบหมาย | ข้อมูลสาธารณะ | ปฏิเสธ | เฉพาะเคสที่มอบหมายและวัตถุประสงค์ที่อนุญาต; แบ่งปันต้องมีสิทธิ์ | ดูสถานะยินยอมที่จำเป็น ไม่ส่งออกทั้งหมดโดยไร้ข้อจำกัด |
| ผู้ดูแลองค์กร | ข้อมูลสาธารณะ | จัดการสมาชิก ไม่ได้สิทธิ์หลักฐาน/เคสอัตโนมัติ | ปฏิเสธหากไม่ได้มอบหมาย | ประวัติขั้นต่ำเฉพาะองค์กร แก้ย้อนหลังไม่ได้ |
| ผู้ดำเนินการย้ายโครงสร้าง | ไม่มีเซสชันแอป | เปลี่ยนโครงสร้างเฉพาะสภาพแวดล้อมที่อนุมัติ | ไม่ใช่สิทธิ์ใช้งานแอปปกติ | แยกบทบาทพิเศษ ห้ามส่งข้อมูลรับรองเข้าเบราว์เซอร์ |

ข้อมูลส่วนตัวในอนาคตต้องตรวจสิทธิ์แบบปฏิเสธโดยปริยายทั้ง endpoint และ RLS
บทบาทแอปต้องไม่เป็นเจ้าของตาราง superuser หรือมี BYPASSRLS ตรวจองค์กรจากสมาชิก
ล้างบริบทการเชื่อมต่อที่นำกลับมาใช้ทุกธุรกรรม บังคับ foreign key ตามองค์กร และทดสอบเมื่อไม่มีบริบท
ไม่มี service/admin key ในไฟล์สาธารณะ ป้องกัน CSRF, IDOR, stored XSS, replay และการไล่เดารายการ
จำกัดอัตราและปิดบังข้อมูลใน log; แยกแคชตามผู้ใช้/องค์กร/สิทธิ์ หรือไม่แคช ห้ามใส่เคสในหน้าสถิตสาธารณะ
แผนนี้ไม่อนุญาตให้ย้ายฐานข้อมูลใด
